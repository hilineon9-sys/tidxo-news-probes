## 1. 產品定位（修正版）

### 核心定位
**港澳大灣區嘅智能資訊中台** — 唔係「另一個新聞 App」，而係理解本地語境、跨源聚合、雙語無障礙嘅資訊層。

### 定位語
> 「Tidxo — 港澳大灣區嘅智能資訊中台。跨源聚合、雙語無障礙、AI 驅動嘅本地洞察。」

### 三層差異化
| 層次 | 策略 | vs 競爭者 |
|------|------|-----------|
| 本地化深度 | 粵語/繁中/英三語、理解港澳政治語境、大灣區覆蓋 | vs Google News |
| 智能聚合+去噪 | 同一事件多源聚合、AI 摘要、立場光譜可視化 | vs 本地新聞 App |
| 雙語無障礙 | 理解港澳用語嘅雙語轉換、專業術語庫、對照閱讀 | vs 所有競爭者 |

## 2. 目標用戶（收窄聚焦）

### Phase 1 種子用戶（P0）
| 用戶群 | 痛點 | 策略 |
|--------|------|------|

| **政策研究者** | 追蹤政策演變、多源對比、歸檔引用 | 主題追蹤、時間線、收藏 |

- 金融從業者（財經新聞聚合）

### Phase 3 大眾用戶（P2）
- 普通新聞消費者
- 大學生（免費教育版）

### 核心場景：媒體人「晨間 scan」
```
07:00  打開 Tidxo → 睇到 AI 整理嘅 10 條晨報
07:03  點擊「橫琴新政策」→ 5 個媒體報導聚合 + 英文切換
07:08  書籤 2 篇 → 分享到 WhatsApp 工作群組
07:10  設定關鍵詞警報 → 完成（10 分鐘 vs 以前 45 分鐘）
```


### 4.2 關鍵架構決策

| 決策 | 選擇 | 理由 |
|------|------|------|
| Phase 1 架構 | **Monolith（模組化）** | 快速驗證，唔好過度設計 |
| Phase 2 通訊 | Kafka 事件驅動 | 服務間解耦、可靠投遞 |
| 數據一致性 | Saga + Outbox Pattern | 最終一致性、可追溯 |
| 服務器選址 | **香港雲（AWS ap-east-1）** | 消除數據跨境顧慮 |
| 移動端 | **React Native (Expo)** | 同 Web 共享 React 生態、一套代碼 |
| 緩存策略 | L1-L5 多層緩存 | 客戶端→CDN→Gateway→Redis→DB |

### 4.3 高可用方案
- **故障分級**：5 級（單服務→區域災難）
- **Circuit Breaker + Fallback**：服務降級
- **目標**：RTO < 5min / RPO < 1min
- **Phase 2**：HK Primary + 異地 DR

## 5. AI 模組設計（優化版）

### 5.1 LLM 混合架構（成本優化 60-70%）

| 比例 | 模型 | 用途 | 成本 |
|------|------|------|------|
| 60% | **本地 Qwen2.5-32B** | 摘要、分類、標籤 | 低 |
| 30% | **GPT-4o-mini** | 翻譯、複雜摘要 | 中 |
| 10% | **GPT-4o** | 深度分析、高質量任務 | 高 |

### 5.2 成本控制策略
- **語義緩存**：相似輸入復用結果
- **批量處理**：合併多篇一次調用
- **智能路由**：根據複雜度選模型

### 5.3 NLP 任務方案
| 任務 | 方案 | 模型 |
|------|------|------|
| 文本分類 | FastText（快速）+ BERT（精準） | 分層架構 |
| 語義相似度 | Embedding | BGE-base-zh-v1.5（中文最優） |
| 關鍵詞提取 | KeyBERT + 港澳術語庫 | 本地 |
| 翻譯（短文本） | DeepL API | - |
| 翻譯（長文本） | NLLB-200 本地模型 | - |
| 粵語處理 | 特徵檢測 + 書面語轉換 | 自定義 |

### 5.4 模型部署
- **開發**：Ollama（簡單快速）
- **生產**：vLLM（高吞吐 PagedAttention）
- **量化**：Q4_K_M（18GB，平衡質量）

### 5.5 成本估算（修正）
| 階段 | 原預算 | 優化後 | 節省 |
|------|--------|--------|------|
| Phase 2 | MOP 3,000 | **MOP 1,200** | 60% |
| Phase 3 | MOP 10,000 | **MOP 3,500** | 65% |

## 6. 前端技術方案（優化版）

### 6.1 技術選型（修正）
| 平台 | 選擇 | 修正說明 |
|------|------|---------|
| Web | **Next.js 14 App Router + RSC** | 升級到最新版 |

### 6.2 性能目標
| 指標 | 目標 |
|------|------|
| LCP（首屏） | < 2.5s |
| 圖片 | WebP 自動優化 + 懶加載 |
| 長列表 | react-virtual 虛擬化 |
| 測試 | 單元 70% + 整合 20% + E2E 10% |

### 6.3 UI 架構
- 三層信息架構：導航層 → 分類層 → 內容層
- 響應式斷點：手機 → 平板 → 桌面

## 14. 關鍵原則

> 1. **唔好過度設計** — Phase 1 monolith 快速驗證
> 2. **速度係唯一優勢** — 3 個月內出 MVP
> 3. **聚焦一件事** — 跨源聚合 + AI 摘要
> 4. **用戶質量 > 數量** — 100 個媒體人 > 10,000 普通用戶
> 5. **先證明有人用，再諗賺錢** — Phase 1-2 完全免費
> 6. **Start small, think big, move fast.**
